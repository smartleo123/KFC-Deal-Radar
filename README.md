# KFC Deal Radar｜肯德基優惠雷達

獨立製作的響應式 KFC 優惠查詢網站。資料優先使用本專案對肯德基點餐 API 已驗證的紀錄，尚未取得官方驗證資料時使用 [Winedays/KCouper](https://github.com/Winedays/KCouper) 社群備援。非肯德基官方網站。

## 功能
- 按折扣率、節省金額、價格、優惠碼排序
- 餐點品項三段式篩選：炸雞、漢堡、蛋撻、薯條／點心、飯食／捲餅、飲料，可對每一類選擇「不限／必須包含／必須排除」，條件可組合
- 自訂預算下限及上限（含邊界值），並保留常用金額捷徑
- 淺色／黑紅深色主題手動切換，使用瀏覽器儲存選擇
- 套餐名稱、優惠碼及餐點關鍵字搜尋
- 最高預算篩選與瀏覽器本地收藏
- 每張卡片可複製分享連結（`?coupon=優惠碼`），收件者開啟後只會看到指定優惠，並可返回全部優惠
- 點擊查看完整餐點和加價選項
- 載入最新公開資料、排除已過期優惠；每張卡片顯示優惠起訖日期（不在頁首顯示來源同步時間）

## 折扣計算與限制

折扣率 = (單點參考價合計 − 優惠售價) / 單點參考價合計 × 100%。

優先利用本站從肯德基點餐 API 擷取的 `data/singles.json` 單點定價，按套餐品項名稱、實際數量計算原價。名稱不同時會嘗試保守別名對應（例如「無糖綠茶」與官網「冰無糖綠茶」）及可拆算的組合（例如兩入蛋撻）；若官方單點價不足，再嘗試公開單點參考價，並標示為混合來源；仍不能完整匹配時，只有來源提供有效 `original_price` 才會計算。未能可靠確定時顯示「原價未確認」，不捏造折扣。卡片保留原價及折扣，價格計算方式統一於優惠列表下方說明；這些是比較基準而非結帳保證價格。

「飲料」已整合於餐點品項三段式篩選，依預設餐點項目名稱判斷是否包含飲料；商品分類屬啟發式規則，可能需要隨來源品項調整。可替換口味不代表套餐預設含飲料。

## 獨立官方 API 收集器（實驗性）

網站同時載入本專案 `data/official.json` 與公開社群優惠清單，按優惠碼合併去重。**官方驗證資料優先覆蓋同碼社群資料**；其他清單不會因已取得部分官方資料就被隱藏。只有經 `olo-api.kfcclub.com.tw` 回覆確認的優惠券才會標為「官方驗證」，其他優惠不顯示驗證標籤。

### 收集流程

`scripts/collect_official.py` 以 Python 標準函式庫與 CookieJar 管理點餐工作階段，查詢：

1. `QueryDeliveryShops`、`QueryDeliveryTime` 初始化門市/日期
2. `getEVoucherAPI` 查詢候選優惠碼
3. `checkCouponProduct` 驗證今日取餐方式與時段
4. `GetQueryFoodDetail` 查詢優惠餐點內容、價格、期限
5. `GetQueryMenu`、`GetQueryFood` 取得官方菜單與單點售價

每四小時 GitHub Actions 嘗試執行一次，預設每次最多檢查 35 個候選代碼，含請求間隔、超時及失敗保護。代碼候選來源包含已驗證代碼、依現有最新代碼**動態調整的掃描視窗**、以及可選的 KCouper 候選代碼；保留各來源掃描游標並輪流檢查，避免永遠只查固定前段代碼。社群候選只用於發現代碼，不以其價格、套餐或有效性作為官方驗證結果。這套方法仍無法保證涵蓋全部有效優惠碼，也不保證某張優惠在每一間店與每一時段適用。

首次由官方 API 成功驗證後，結果儲存至 `data/official.json`、單點價格儲存至 `data/singles.json`，並提交至 `main` 供 GitHub Pages 部署使用。未通過驗證時保留舊快照、不覆蓋成空資料。

### 哪些部分仍是設定值，不能保證什麼

- **優惠內容不是 hardcode**：優惠碼、名稱、價格與期限來自肯德基 API 實際回應或當次讀取的公開社群資料，程式不內建固定優惠清單。
- **設定仍有預設值**：每次查詢上限 `KFC_MAX_CHECKS`（目前 workflow 為 35）、請求間隔、掃描視窗半徑 `KFC_SCAN_MARGIN`（目前為 2000）、預設查詢門市 `TWI104`、部分有效時段組合與資料來源網址；這些是系統限制與配置，不是優惠資料。
- **獨立尋找新代碼無完整保證**：優惠碼不一定連號，未公開／會員專屬優惠可能不在掃描視窗內；社群清單若停止更新，本站也可能較慢發現新系列。
- **資料有效期與警示**：前端會依優惠期限過濾，但成功下載不等於來源真的更新。GitHub Actions 排程可能延後或因平台政策暫停。正式使用仍應以肯德基結帳結果為準。

### 排程與資料新鮮度

- **官方 API**：預計每四小時增量查詢，更新不是秒級即時。來源時間仍保留在資料檔與 GitHub Actions 紀錄，不再顯示於網站頁首。
- **社群補充**：每次開啟網站仍會讀取最新社群清單，與官方已驗證記錄依優惠碼合併；原有每半小時發布的快照作為連線備援。社群補充資料仍可能有過期、門市或用餐時段限制。
- **數量差異修正**：舊版只要有官方資料，就會直接跳過社群清單，導致總數被限縮至最初驗證的約 20 張；新版合併來源，按優惠碼去重，僅在已驗證優惠卡片上顯示「官方驗證」。
- **使用限制**：這些是肯德基網域上的點餐端點，非經確認授權的公開第三方 API；可能拒絕請求或改版。請遵守網站適用條款，不要提高速率造成服務負擔。
- **失敗處理**：官方 API 連線、有效券數量與是否建立快照，可從 Actions 的 `Collect KFC official API data` 執行紀錄確認。僅有程式碼提交並不代表 API 已連線成功。

手動執行（需網路）：

```bash
python3 scripts/collect_official.py --out data
python3 -m http.server 8000
```

## 發布至 GitHub Pages

1. 在 GitHub 建立 **public** repository，建議命名 `KFC-Deal-Radar`。
2. 將本資料夾所有檔案（含 `.nojekyll`）提交到預設分支根目錄。
3. 進入 **Settings → Pages → Build and deployment**，將 **Source** 設為 **GitHub Actions**（首次啟用需要 Repo 管理員在 GitHub 網站上操作）。
4. 前往 **Actions → Deploy GitHub Pages**，若沒有自動部署成功，點選 **Run workflow** 重新部署；部署成功後再開啟網站。預期網址：`https://smartleo123.github.io/KFC-Deal-Radar/`（前提是 repo 名稱和所有者相同）。

純 HTML/CSS/JS，無需 Node、後端或 API 金鑰。
